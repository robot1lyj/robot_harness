# 性能方法与样例结果

Harness 的效率目标是：完成相同任务时，减少不必要的模型介入、工具往返和重复上下文，同时保留结果判据与执行记录。设备控制周期和算法推理速度由各自实现决定。

## 已实现的方法

| 方法 | 减少什么 | 适用范围 |
|---|---|---|
| 代码技能与完整目标配方 | 稳定流程内部的逐步模型决策 | 代码已覆盖目标及完成条件时可直接执行；额外目标仍需 Agent 判断 |
| 技能简介检索、正文按需加载 | 未选中技能和无关历史占用的上下文 | 技能目录与任务视图 |
| 会话复用与变化块 | 重复建立会话、重复发送相同资料 | 框架管理的 Agent 会话；外部客户端怎样组织上下文取决于其实现 |
| 宿主等待终态或有效事件 | 模型机械查询“是否完成” | 框架管理的执行与等待路径；仍保留取消和状态查询 |
| 有效绑定与版本复用 | 下一任务重复发现和验证同一选择 | 已校验的支持范围，相关依赖变化后重新检查 |

## 已有真实 Agent 样例

记录日期为 2026-10-17。对比同一框架的旧调用路径与会话/上下文优化后的路径；两侧均使用 `gpt-6.1-sol`、`xhigh`，任务输入、动作参数、超时、模拟设备条件和成功判据一致。下表每一行各一组成功的前后样例，执行对象是模拟能力。

| 场景 | 工具调用次数：前 → 后 | 非缓存输入 token：前 → 后 | 端到端耗时：前 → 后 |
|---|---:|---:|---:|
| 正常完成 | 10 → 5 | 39,969 → 32,728 | 50.323 → 35.878 秒 |
| 可恢复失败后完成 | 12 → 8 | 25,782 → 21,756 | 50.924 → 43.735 秒 |

token 来自客户端报告。对应的总输入（含缓存）分别为正常任务 335,777 → 111,576、恢复任务 403,382 → 172,284；输出分别为 1,013 → 666 和 1,192 → 1,195。总输入、非缓存输入及工具正文大小是不同指标，费用没有单独测量。

这些样例支持“调用次数和重复输入可以减少”的结论。每类只有一次成功前后样本，部分运行时间重叠，并另有服务容量失败记录；时间受缓存、服务负载和执行顺序影响。这不是稳定加速比、P95、成功率或费用基准，也不是当前发布版重新测量的结果。后续版本保留相关软件回归，未重复这些模型试用。

## 软件与协议验证

独立于上述真实 Agent 样例，确定性协议夹具验证了同任务会话复用、变化块、取消等待和重启接续。正常场景的后续决定相对同一装配器完整视图少传 6,225 字节；恢复场景两个后续决定合计少传 12,450 字节。这是 UTF-8 正文字节，不是 token 或费用。

公开用例见 [会话与上下文测试](../tests/test_c01_sessions.py)；实现入口见 [Agent 宿主](../src/robot_rsi/agent_host.py)和[任务视图](../src/robot_rsi/task_context.py)。这些测试可以验证机制，不替代真实模型的性能测量。

## 使用方怎样评估

选择自己的代表任务，固定输入、能力版本、模型配置和结果判据，同时记录：

- 完成结果、失败类型及是否需要援助。
- 工具调用与模型用量；输入 token 分开记录缓存和非缓存。
- 端到端时间与工具执行时间，避免把模型、网络和设备等待混成算法耗时。
- 实际安装版本及运行条件，保留失败和退化样例。

目前还没有跨机器人基准、稳定延迟分布、真实双模型教学收益或真实硬件效果数据。接入自己的环境后，以上方法和已验证机制可作为测量起点。
