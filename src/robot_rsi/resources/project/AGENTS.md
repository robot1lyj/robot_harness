# Robot usage project

This directory owns local extensions, skills, profiles, assets and new state under `.rsi/state`.
Harness is a fixed installed dependency; do not replace this project with the framework checkout.
When a controlled host entry is supplied, use its fixed installation and writable scope. Build local
candidates here; the host update path preserves core references. This text is not a permission boundary.

Before integration work, run `uv run --no-sync robot-rsi guide agent` to load the installed base,
onboarding workflow and project guide. Read `profiles/development.json` for the selected source
and `profiles/runtime.json` for runtime configuration. Retain your host's existing file/terminal
tools: implement authorized requests here, build/install fixed wheels and use the real Harness
catalogs and `task_run`. Do not launch a read-only child Agent to replace implementation.

Keep legacy sources unchanged. Initialization grants no device access; use actual authorization
and capability evidence. Preserve user files/configuration/history during dependency updates.
For completed development features/fixes, follow the installed project guide: verify, update the
existing fact owner/checkpoint, and commit only this work locally; report the actual SHA and gaps.
The controlled `launch.py coding` entry captures one local handoff and feeds back only missing items
once in the same session. Other desktop/MCP hosts need their own exit handling; valid checks stay valid.
Use workspace_context to resume from existing owners; ordinary runtime needs no Git action.
Answer in Chinese, reporting actual results, freshness and gaps.
